# Аудит страниц LuCI

Этап 2 полировки, снято 2026-11-01 на стенде `scripts/luci-stand.sh` (LuCI на
OpenWrt 25.12.6, данные синтетические). Код страниц не менялся. Сортировка и
исправления - этапы 3 и 4.

## Как читать

- **Серьёзность:** высокая - теряется настройка или управление, либо состояние
  показано ложно; средняя - действие или сообщение вводит в заблуждение, есть обход;
  низкая - мешает, но не вредит.
- **Подтверждено:** `стенд` - наблюдал действием на стенде; `стенд+код` - наблюдал
  симптом, причину прочитал в коде; `код` - только чтение, на стенде не воспроизводилось.
- **Тип:** `дефект` исправляется по ходу работ, `вкус` решает пользователь по снимкам.
- **Стенд:** отмечено, если причина или часть причины в самом стенде.
- Снимки лежат в `build/luci-stand/` (каталог не отслеживается): `a2-<режим>/<страница>/`
  - прогоны `probe`, `a2-walk/` - снимки обхода. Они пересоздаются командами из
  `AGENTS.md`, раздел «Проверка интерфейса».
- Приём «сбой чтения, потом запись»: `mode error`, открыть страницу, затем
  `docker exec ikev2-luci-stand sh -c 'echo full >/tmp/stand/mode'`. Данные `full` и
  `error` одинаковы, поэтому страница показывает сбой чтения, а запись идёт в настоящий
  helper. Так выглядит разовый сбой на роутере.

## Самое серьёзное

1. **L-01:** после сбоя чтения любая правка на `routing` отправляет пустой список
   привязок сервисов к туннелям.
2. **L-02:** сбой Set up remote clients оставляет настройку наполовину сделанной:
   подсеть закреплена навсегда, после перезагрузки следа ошибки нет.
3. **L-03:** без настройки удалённых клиентов нельзя управлять VPN-пользователями.
4. **L-04, L-06, L-07:** сбой чтения показан как настоящая настройка и как ложные статусы.
5. **A-01:** действия на 11 и 60 секунд идут без видимого текста, кнопка пуста.

## Сортировка

Этап 3, решения пользователя от 2026-11-01.

- **Вид (G-16):** страницы приложения целиком оформляются по дизайн-коду «Патина и
  графит»; рамка LuCI остаётся темой. Отдельным проходом после дефектов; контраст G-03,
  G-04 и фокус K-09 решаются в нём же.
- **Загрузка (G-01):** каркас страницы показывается сразу, у области данных свои
  состояния загрузки, готовности, пустоты и ошибки.
- **Прогресс (A-01):** текст прогресса виден, если действие идёт дольше 3 с; короткие
  действия как есть.
- **Подтверждения (T-04):** спрашивать перед Reset to generated и Revoke; Disconnect и
  Pause без вопроса.
- **Остальное:** всё с пометкой `дефект` исправляется. Пометки `вкус` без решения выше
  (A-11, G-14, G-15, T-07, T-08, T-10) показываются пользователю со снимками в проходе
  вида.

Порядок исправлений:

1. Потеря настройки и управления: L-01, L-02, L-03.
2. Сбой чтения как состояние «недоступно» и запрет записи: L-04, L-06, L-07, затем L-05,
   L-08.
3. Долгие действия: A-01, A-02, затем остальные из раздела 2.
4. Тексты: T-01, T-02, T-03, T-06, затем остальные.
5. Клавиатура и геометрия: K-01, K-02, G-02, G-05, затем остальные.
6. Каркас страниц (G-01).
7. Вид по дизайн-коду (G-16 и всё, что в нём решается).

# IKEv2 Manager для OpenWrt

[English](README.md)

[![CI](https://github.com/Nikitid/luci-app-ikev2-manager/actions/workflows/ci.yml/badge.svg)](https://github.com/Nikitid/luci-app-ikev2-manager/actions/workflows/ci.yml)

Пакет `luci-app-ikev2-manager` - LuCI-приложение для исходящего IKEv2-туннеля,
входящего IKEv2-сервера и выборочной маршрутизации IPv4-трафика в OpenWrt. В
качестве удалённого шлюза можно использовать [IKEv2 Manager для
Ubuntu](https://github.com/Nikitid/ikev2-ubuntu).

![Страница Overview в IKEv2 Manager](docs/images/overview.png)

## Возможности

- исходящий IKEv2/EAP-клиент через XFRM-интерфейс, до семи туннелей,
  которые подменяют друг друга;
- маршрутизация сервисов, доменов, IPv4-адресов и CIDR через VPN, каждого
  сервиса, ручного списка и устройства с полным туннелем - через выбранный для
  него туннель, с переходом на другой туннель или с привязкой к своему;
- режимы устройств: выбранные домены, весь трафик, прямой WAN, отдельные
  исключения DNS/DPI и пресет полного исключения из управления;
- FakeIP/TProxy для доменов и собственная fail-closed маршрутизация по
  спискам без пакета pbr;
- входящий IKEv2/EAP-сервер с глобальными и индивидуальными правилами доступа
  пользователей к роутеру, отдельным публичным портам, Интернету и локальным
  IPv4-адресам;
- управляемый доступ для компьютеров с Windows и macOS: администратор публикует сервисы
  каталога и приглашает устройство, а его клиент отправляет только эти сервисы
  через входящий сервер и выбранный туннель и блокирует их в остальных случаях;
- виджет состояния исходящего туннеля, маршрутизации и активных входящих
  VPN-клиентов в Status -> Overview;
- DNS upstream через UDP, TCP, DoT, DoH, HTTP/3, DoQ или DNSCrypt, включая
  явный аварийный DNS от WAN-провайдера и независимые группы резолверов
  для заданных доменных суффиксов;
- адреса и домены, которые никогда не идут через туннель и сильнее любого
  выбранного сервиса, при желании и для устройств с полным туннелем;
- профили входящих клиентов для Apple, Android (приложение strongSwan) и
  Windows VPNv2/NRPT, включая универсальное приложение Windows и отдельные
  профили VPNv2 XML без PowerShell, и одноразовую QR-ссылку, по которой профиль
  ставится на телефон без файла на компьютере;
- зашифрованная копия настроек, которая восстанавливается на том же роутере
  или переносится на другой, сохраняя его собственные сети;
- ACME и интерфейс LuCI на русском и английском языках.

## Требования

- официальный OpenWrt `24.10.x`;
- firewall4/nftables, IPv4 WAN и официальные репозитории пакетов;
- место для strongSwan, sing-box, `dnsmasq-full` и `dnsproxy`;
- для управляемого доступа с компьютеров: Windows 10 22H2 или Windows 11
  на x64, Windows 11 24H2 на ARM64 либо macOS 14 и новее на Apple silicon.

OpenWrt `25.12.x` поддерживается экспериментально на проверенных целях
`mediatek/filogic` и `aarch64_cortex-a53`. Vendor firmware, snapshots и
firewall3 не поддерживаются.

## Установка

### OpenWrt 24.10

Скачайте последний `luci-app-ikev2-manager_*_all.ipk` из
[Releases](https://github.com/Nikitid/luci-app-ikev2-manager/releases) и
загрузите его через:

```text
System -> Software -> Upload Package
```

После установки откройте:

```text
Services -> IKEv2 Manager -> Overview
```

Установите зависимости, выберите WAN и защищаемые сети, включите управляемый
режим и настройте туннель. CLI-установка, миграция и восстановление описаны в
[Operations](docs/OPERATIONS.md).

### OpenWrt 25.12

```sh
wget -O /tmp/nikitid-feed.sh \
  https://raw.githubusercontent.com/Nikitid/openwrt-feed/feed/install.sh
sh /tmp/nikitid-feed.sh luci-app-ikev2-manager
```

Установщик проверяет публичный ключ издателя по закреплённой контрольной сумме,
подключает общий подписанный репозиторий приложений Nikitid и устанавливает
только указанный пакет. Установка, выполненная до появления общего репозитория,
переводится на него автоматически при обновлении пакета.

Последующие обновления:

```sh
apk update
apk upgrade luci-app-ikev2-manager
```

Команда обновляет только IKEv2 Manager, а не все системные пакеты.

## Маршрутизация

Доменные правила используют sing-box FakeIP и nftables TProxy. Правила для
IPv4-адресов и CIDR работают без DNS. Если исходящий туннель недоступен,
выбранный трафик блокируется, а остальной продолжает идти через WAN.

Если туннелей несколько, все включенные остаются подключенными. Когда туннель
сервиса не работает или подключен, но трафик через него не проходит, его
трафик в течение минуты переходит на следующий работающий туннель и
возвращается через две минуты после того, как свой туннель снова поднялся.
Сервис, которому нельзя выходить из другой страны, привязывается к своему
туннелю: пока туннель не работает, сервис блокируется. В WAN трафик не уходит
никогда: если не работает ни один туннель, он блокируется. Перенос сервиса на
другой туннель закрывает открытые соединения этого сервиса и не трогает
остальные.

DNS для выбранных направлений настраивается на вкладке исходящего туннеля.
Первый DoH-сервер основной, следующие используются как упорядоченный резерв.
TLS-проверки, рабочий bootstrap и сами DoH-соединения привязаны к `ipsec-out`; автоматического
возврата выбранных направлений в WAN нет.

Для доменной маршрутизации клиенты должны использовать DNS роутера. Browser
DoH и Android Private DNS могут обходить классификацию. В надежном режиме
роутер отвечает "нет такого имени" на имена, которые Firefox и Apple
опубликовали для этой цели: Firefox остается на DNS роутера, а iCloud Private
Relay в этой сети отключается.

### Waypoint и другой VPN

Системный прокси и VPN-расширение браузера могут отправлять выбранные сервисы
через другой VPN в обход Waypoint. Kill Switch чаще блокирует доступ; это
само по себе не доказывает утечку. Отключение Kill Switch убирает защиту другого
VPN при обрыве его соединения.

Адреса для исключений копируйте из правой части окна Waypoint: IP сервера,
сети сервисов и туннеля. Домен сервера добавляйте, если программа принимает домены.

| Программа | Что настроить |
| --- | --- |
| v2rayN, Throne, Clash Verge Rev, Hiddify | Выключите "Системный прокси", включите TUN. В Hiddify выберите режим службы "VPN". |
| WireGuard, Windows | Туннель -> "Редактировать" -> снимите "Блокировать трафик, идущий мимо туннеля (kill-switch)" -> "Сохранить". |
| WireGuard, macOS | Оставьте стандартный маршрут `0.0.0.0/0`. Не заменяйте его двумя маршрутами `/1`: в проверке это нарушало соединение Waypoint. |
| AmneziaVPN, Windows | "Настройки" -> "Соединение" -> "KillSwitch" -> выключить. В раздельном туннелировании выберите "Адреса из списка не должны открываться через VPN", добавьте адреса Waypoint и переподключитесь. Полный туннель не проверен. |
| AmneziaVPN, macOS | Отключите Amnezia на время работы с Waypoint: в версии 4.8.21 отключение Kill Switch и исключения не устранили конфликт. |
| Proton VPN, Windows | "Раздельное туннелирование" -> включить -> "Режим исключения" -> "Исключенные IP-адреса" -> адреса Waypoint -> "Применить" или "Переподключиться". Функция требует платного тарифа. |
| ExpressVPN, Windows | "Профиль" -> "Раздельное туннелирование" -> включить -> "Добавить IP" -> IP и сети Waypoint. |
| AdGuard | **AdGuard VPN:** "Исключения" -> "Сайты" -> режим "VPN включен везде, кроме сайтов, которые вы добавили" -> домены нужных сервисов и сервера Waypoint. При блокировке: "Настройки" -> "Настройки приложения" -> "Kill Switch" -> выключить. **Блокировщик AdGuard:** при сбое DNS откройте "Настройки" -> "DNS-защита" -> выключить. Это разные приложения. |
| Mullvad, корпоративный VPN | Отключите другой VPN на время работы с Waypoint. Исключение приложения не равно исключению адресов Waypoint; совместимость не проверена. |
| VPN-расширение браузера | Отключите расширение. |

Если системный прокси остался включен:

- **Windows:** "Параметры" -> "Сеть и Интернет" -> "Прокси-сервер" -> выключить "Использовать прокси-сервер" и "Использовать сценарий установки".
- **macOS:** "Системные настройки" -> "Сеть" -> нужная служба -> "Подробнее" -> "Прокси" -> выключить HTTP, HTTPS, SOCKS и автонастройку прокси.

TUN проверен с v2rayN, Throne и Clash на Windows, с Clash на macOS. Интерфейс
Hiddify и Throne на macOS не проверены. Proton и AdGuard VPN не проверены без
входа в аккаунт; ExpressVPN и Mullvad недоступны в бесплатном тестировании.
Настройки провайдеров приведены по их документации и не означают проверенную
совместимость с Waypoint.

Документация настроек: [Proton](https://protonvpn.com/support/protonvpn-split-tunneling),
[ExpressVPN](https://www.expressvpn.com/support/knowledge-hub/split-tunneling-desktop/),
[AdGuard VPN](https://github.com/AdguardTeam/KnowledgeBaseVPN/blob/master/docs/adguard-vpn-for-windows/overview.md).

## Списки доменов

Списки проекта находятся в `luci-ikev2-domains/local-services/`.
Дополнительные списки загружаются из
[`itdoginfo/allow-domains`](https://github.com/itdoginfo/allow-domains) и не
входят в IPK. Сети Zoom Meetings загружаются из официального списка Zoom и
объединяются со снимком из пакета. Готовый сервис можно изменить в LuCI; это
создаёт локальное полное переопределение, которое не смешивается с общим
списком доменов.
Там же можно создавать отдельные свои сервисы. Они хранятся в
`/etc/ikev2-manager/services.d/` и сохраняются при обновлении. Условия использования
внешних списков описаны в [NOTICE](NOTICE).

## Поддержка

Вопросы и сообщения об ошибках - в
[Issues](https://github.com/Nikitid/luci-app-ikev2-manager/issues/new/choose), выберите
подходящую форму, и приложите отчёт кнопкой **Скачать отчёт** на странице
Обзор, в разделе Системные компоненты: пароли, ключи и токены в него не попадают, а
публичные и MAC-адреса, имена хостов и пользователей заменены. Прочитайте его
перед отправкой. Об уязвимости сообщайте приватно через
[security advisory](https://github.com/Nikitid/luci-app-ikev2-manager/security/advisories/new).
Можно писать по-русски или по-английски.
